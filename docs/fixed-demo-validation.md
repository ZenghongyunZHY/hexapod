## 当前固定参数

用户反馈初稿站得太矮，要求提高站姿、加大步幅和加快。当前右腿目标 `[500,550,200]`，左腿 `[500,450,800]`；大腿上抬12°，小腿相对下折72°，绝对斜率向下60°。按 CAD 二维腿长估算，第二轴到金属脚端的竖直距离由61.12增至82.03mm，增加约21mm；不是实测机身离地高度，未包括根部安装高度和胶垫触点。

偏航摆幅由±20改为±35位置单位；抬腿大腿/小腿增量由25/10改为35/15。抬腿、落地300ms，前摆、回中400ms，各等待100ms；站姿过渡仍3000ms并等待600ms。仍为6个完整周期、12次行走摆动落地，随后分组回中，44帧首尾站姿相同。含通信预算的计划由40.4缩至32秒，实际时长受回读与补读影响。

这些参数是按用户要求选定的候选帧，尚未实物验证；不是实测角度或机械限位。[使用说明](../ros2_ws/src/hexapod_demo/README.md) · [结构化记录](../outputs/fixed-demo-validation.json)。此前的 [20°初稿示意](../outputs/demo-standing-candidate.png) 是历史图，不代表当前v2参数。

## 不动原因与修复

用户截图显示：启动电压8504mV，18只位置读齐，初始位置已经接近旧站姿；执行首个站立帧后出现 `Expected 18 position responses`，因此尚未进入第一组抬腿。

只读真实UART诊断捕获到一次合法17只回包，缺ID7；后续18只查询与分组查询又读齐。软件现在在原有总查询期限内最多针对缺失ID补读两次，显示 `POSITION_RETRY`，读齐后再继续。持续缺失、重复ID和错误数据仍停止；不以缓存或默认值代替反馈。

## 当前验证结果

- Pi 4B / aarch64 / ROS 2 Jazzy Release 编译与C++协议/有限周期测试通过。
- 虚拟UART验证通过：默认不打开串口、探测无动作；持续缺失、重复ID、错误计数、电压异常和超时均阻止执行；偶发缺ID7可定向补读，包括首个动作后的读回；Ctrl+C按实测当前位置保持；完整44帧、6周期、首尾同站姿，无动作组或卸力命令。
- 电压边界验证：5999mV拒绝，6000/8661/8700mV接受，8701mV拒绝。两个demo仍按用户临时要求使用6000～8700mV；规格书保持6000～8400mV。
- 本地和树莓派12个源码文件的SHA-256一致。
- 新版真实只读探测通过：8259mV，全部18只舵机位置读齐，输出 `PROBE_OK`。记录位置见结构化文件。

代理没有向真实舵机发送动作命令。用户已观察旧站姿并反馈高度，新v2站姿与步态效果仍待用户实物核对；虚拟测试不证明实际能正常行走。

## 运行

```bash
source /opt/ros/jazzy/setup.bash
source ~/hexapod_ws/install/setup.bash
ros2 run hexapod_demo stand_demo --execute
ros2 run hexapod_demo walk_demo --execute
```

先核对新站姿，再运行6个完整周期。Ctrl+C停止后续帧并尝试保持当前位置；实际效果仍需确认偏航方向、关节活动范围、接触与摩擦。
